## SMILES-2026: Zero-Order Optimization of ResNet18 under Compute Constraints 

**Задача.** Обучение глубокой нейросети (ResNet18) в условиях, когда аналитические градиенты недоступны, а вычислительный бюджет жёстко ограничен (≤ 256 forward passes)

**Подход.**
- **Zero-Order Optimization (SPSA)** — градиент аппроксимируется через симметричные возмущения параметров без backpropagation:

$$
g(\theta) \approx \frac{\mathcal{L}(\theta + \epsilon) - \mathcal{L}(\theta - \epsilon)}{2\epsilon}
$$

- **Гибридная схема оптимизации** — SPSA для исследования пространства параметров в связке с Adam для стабилизации обновлений
- **Стратегия обучения** — curriculum learning, поэтапная разморозка слоёв (staged unfreezing), стабилизация в low-compute режиме

**Результат.** Accuracy выросла с 4.12% до 21.47% при сохранении жёсткого ограничения на число forward-pass операций и стабильной сходимости

**Стек:** Python, PyTorch, NumPy

## RAGNAROK 

Модульный, независимый от LLM фреймворк для комплексной оценки RAG-пайплайнов (Retrieval-Augmented Generation), разработанный в рамках проекта **SMILES-2026**.

**Что делает фреймворк:**
- Оценивает retrieval, генерацию и бизнес-эффект RAG-пайплайна и сводит результат к единому **Business Score (0–100)**.
- Автоматически диагностирует, **на каком этапе** пайплайна и **по какой причине** возникает проблема (чанкинг, эмбеддинги, реранкинг, генерация, бизнес-ограничения).
- Не требует обращения к LLM для базовых метрик — работает на локальных embedding/NLI-моделях; LLM-судья доступен как опциональное дополнение.

**Ключевые возможности:**
- 5-этапная диагностика retrieval-пайплайна с автоматическим определением узкого места (bottleneck): доступность данных → качество чанкинга → качество эмбеддингов → качество ретрива (Hit Rate@k, Precision@k, Recall@k, NDCG@k, MRR@k) → эффект реранкинга.
- Метрики генерации: faithfulness (NLI-энтейлмент, детект галлюцинаций), Semantic Footprint Coverage (детект пропусков), Information Density Score (детект избыточности).
- Бизнес-метрики: стоимость (токены / GPU-часы), латентность, доверие (trust), эффективность покрытия контекста, композитный Business Score с настраиваемыми весами.
- Готовые пресеты конфигурации (safety-first, speed-first, cost-saving, medical, customer support, research и др.), выбор по названию, свободному тексту или числовым приоритетам.
- Структурированные отчёты (Markdown/HTML/dict) без обращения к LLM, либо LLM-нарратив как опция.
- Покрытие тестами (pytest), YAML-конфигурация, синтетический набор из 30 размеченных тест-кейсов для проверки классификатора ошибок.

**Стек:** Python

🔗 Репозиторий: [RAGNAROK](https://github.com/aameliig/RAGNAROK)

## FEVM Solver - Математическое моделирование процесса дыхания в легких человека

C++ FEM/FVM-солвер, моделирующий механику дыхания лёгкого как **двухфазную пористую среду** — упругий скелет ткани, насыщенный газом (воздухом). Связанная задача: гиперупругая механика скелета в конечных деформациях + фильтрация газа по закону Дарси
 
**Модель:**
- Сетка: 7 572 узла, 36 994 тетраэдральных конечных элемента
- Один дыхательный цикл — 4 с (вдох 0→2 с, выдох 2→4 с), шаг по времени 0.002 с (2000 шагов)
- Скелет ткани — гиперупругая формулировка через главные вытяжки (собственные значения тензора деформаций), с начальным напряжённым состоянием в равновесии с атмосферным давлением
- Газовая фаза — фильтрация по закону Дарси через грани конечных элементов
- Единственный "двигатель" дыхательного цикла — кинематическое граничное условие на диафрагме; входы бронхов граничат с атмосферным давлением (условие "открытого конца трубки")
**Что реализовано:**
- Факториальный план 2×2: два закона проницаемости (постоянная k = k₀ vs растущая при расширении альвеол k ~ (v/v₀)², упрощённый аналог уравнения Козени-Кармана) × сегментация лёгкого на 18 анатомических бронхолёгочных сегментов (10 правое лёгкое, 8 левое), в которых поток газа между разными сегментами блокируется
- Рефакторинг: 4 изначально жёстко зашитых сборки солвера (v01–v04, теперь в архиве) объединены в один бинарник с рантайм-флагами (`--kozeny`, `--segmentation`)
- Сценарии без пересборки — входы бронхов и граничные условия задаются текстовыми файлами (`inlets.txt`, `conditions.txt`), включая произвольные поля по зонам (например, локальное изменение проницаемости в зоне)
- Найдены и исправлены два содержательных бага: разрыв face-соседства на границах сегментов (артефактное падение давления до −7000 Па, исправлено flood-fill переназначением) и рассинхронизация индексации источников газа (0-based/1-based), из-за которой два сегмента не получали газа
- Выходные данные — временные ряды концентрации газа, плотности и давления по каждому источнику/сегменту, экспортируемые в VTU (для визуализации) и CSV (для последующего анализа и построения графиков)
**Стек:** C++, Eigen, VTK, Python
 
**Публикация:** результаты представлены на XVIII Всероссийской научно-практической конференции молодых учёных и специалистов Роспотребнадзора «Современные проблемы эпидемиологии, микробиологии и гигиены» (Пермь, 13–14 мая 2026 г.) — [материалы конференции](https://fcrisk.ru/sites/default/files/upload/conference/3159/fcrisk_conf_2026-05_materials-1.pdf)

# VR-тренажёр установки ЭЛОУ (Лукойл-Пермнефтеоргсинтез)

Командный проект: VR-тренажёр электрообессоливающей установки (ЭЛОУ) на базе Unity и UniSim Design, разработанный для «Лукойл-Пермнефтеоргсинтез».

## Задача

ЭЛОУ — первое звено технологической цепи нефтеперерабатывающего завода: установка удаляет соли и воду из нефти перед переработкой, предотвращая коррозию оборудования и повышая качество сырья. Обучение новых специалистов и повышение квалификации инженеров на реальном оборудовании — дорого и рискованно, поэтому цель проекта — построить VR-тренажёр ЭЛОУ на базе UniSim Design для отработки процессов в безопасной виртуальной среде.

## Роли в команде

Участвовал в проекте на трёх ролях одновременно:
- **Менеджер** — планирование работы, ведение документации, постановка и корректировка задач, анализ хода разработки
- **Unity-разработчик** — настройка проекта под VR (Oculus, HTC Vive), реализация перемещения и взаимодействия в виртуальной среде, сборка окружения ЭЛОУ
- **3D-специалист / дизайнер** — работа по чертежам установки, моделирование и детализация объектов (включая горизонтальный электродегидратор, ресивер воздуха), наложение текстур, оптимизация моделей под VR, интерфейс и элементы VR-навигации

## Дорожная карта проекта

1. Изучение технологии, процессов и оборудования ЭЛОУ
2. 3D-моделирование объектов в Blender, сборка и настройка виртуального окружения в Unity, UI
3. Первый VR-запуск: оптимизация 3D-моделей, настройка Unity под VR, тестирование
4. Настройка VR-механик: перемещение, взаимодействие с окружением, логика процессов ЭЛОУ
5. Интеграция с UniSim Design и настройка технологических процессов
6. Тестирование, поиск багов, пилотный запуск на аудитории, релиз

## Что сделано

- Изучены чертежи установки, на их основе собрана сцена в Unity с точным расположением оборудования
- Смоделированы и детализированы ключевые объекты установки (горизонтальный электродегидратор, ресивер воздуха и др.), настроена работа с текстурами
- Проработана логика взаимодействия UniSim Design и виртуальной сцены: действия пользователя в VR (например, закрытие вентиля) передаются в архитектуру UniSim, симуляция процесса возвращает «реакцию» окружения (изменение давления в трубах и т.п.)

## Стек

Unity, Blender (3D-моделирование), UniSim Design, VR (Oculus, HTC Vive)

# Пульс ИИ — агент мониторинга ключевых показателей развития ИИ в России

Автоматический Python-агент для сбора, хранения и отчётности по 5 ключевым метрикам развития искусственного интеллекта в России — единый пайплайн вместо разрозненных ручных подсчётов. Разработан в рамках стажировки, связанной со Сколково.

## Метрики мониторинга

| № | Метрика | Что измеряет |
|---|---|---|
| М1 | Число топ-публикаций РФ по ИИ | Статьи с российской аффилиацией в топовых ИИ-конференциях и журналах (NeurIPS, ICML, CVPR, ACL, Nature и др.) |
| М2 | Квалифицированные ИИ-исследователи | Число специалистов, ведущих исследовательскую работу в области ИИ |
| М3 | ЕГЭ 81+ и олимпиадники | Выпускники с высокими баллами по математике/информатике плюс призёры профильных олимпиад |
| М4 | Доля исследователей до 39 лет | Возрастная структура исследовательских кадров страны |
| М5 | Student researchers в ИИ-центрах | Студенты-исследователи в Иннополисе, МФТИ, ИТМО, ВШЭ, Сколтехе |

## Источники данных — честная трёхуровневая схема

Для каждой метрики метод получения значения фиксируется явно и никогда не выдаётся за то, чем не является:

1. **Реальный API** — где он есть и стабилен (OpenAlex — основной источник М1, сверка через CVF Open Access и ACL Anthology)
2. **Парсинг отчёта** по URL — для метрик, у которых нет открытого API, но есть регулярные PDF/HTML/XLSX-отчёты (data.gov.ru, Рособрнадзор/ФИПИ, форма 1-НТ Росстата, ВШЭ)
3. **Ручной ввод** — фолбэк в `manual_data.yaml`, когда стабильного источника нет или парсинг не сработал (актуально для М2, частично М5)

Метод получения (`api` / `pdf_parse` / `manual`) хранится в базе вместе с каждым значением метрики.

## Архитектура

- **Единый интерфейс адаптера:** `fetch(year) → value, source, method` — одинаковый контракт для всех 5 метрик, независимо от источника
- **Общая схема БД** (SQLite): `metric_id, year, value, source, method` — один дашборд поверх всех метрик без конвертации форматов
- **Пайплайн:** адаптер → SQLite → экспорт в CSV / PDF / DOCX одной командой
- **Дедупликация публикаций** между источниками (OpenAlex + Semantic Scholar и др.) для метрики М1
- Общая структура репозитория вместо разрозненных папок у каждого стажёра, review через pull request перед слиянием в основную ветку

## Ограничения

- У метрик М2–М5 нет открытого стабильного API — URL отчёта меняется год от года, и это не решается «раз и навсегда»
- OpenAlex с февраля 2026 требует API-ключ на каждый запрос
- DBLP блокирует автоматических клиентов через `robots.txt`
- Эвристика с определением учёной степени по тексту публикации (М2) нуждается в ручной проверке

## Результаты (2026)

| Метрика | Значение |
|---|---|
| М1 — публикации | 23 |
| М2 — исследователи с PhD | 105 |
| М2 alt — авторы публикаций | 313 |
| М3 — ЕГЭ 81+ / олимпиады | 47 000 |
| М4 — исследователи < 39 лет | 46.5% |
| М5 — студенты в ИИ-центрах | 800 |

Полный сбор всех метрик — `python main.py --only 1` — занимает около 30 секунд и формирует `data/pulse_ai.db`, `metrics_export.csv` и детальный список публикаций с DOI и авторами для ручной сверки.
